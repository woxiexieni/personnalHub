# 事件反思与行为模式 v0.1（性格改变的需求边界）

> 状态：**已确认（2026-10-18）**，三项已定；§13 为五个月使用模拟暴露的 5 个缺口，已并入边界
> 上游依据：`事件时间块与OPDCA-v0.1.md`（时间块、目标层、OPDCA 骨架）、`产品需求总览-v1.0.md`
> 定位：**事件反思不是"写日记"，是"模式的生产车间"。** 本文件定义它和练习记录、时间块的关系
> 版本：R5（排在 R2 时间块、R3 轻量复盘、R4 计划之后）

---

## 0. 一句话

**深度写只发生一次（每个模式一次），之后靠两次点击累积证据。**

---

## 1. 五个模型，只有一个是"循环"

这是本文档最重要的一条边界。模型清单越长，系统死得越快。

| 模型 | 在系统里是什么 | 不是什么 |
|---|---|---|
| **OPDCA** | **唯一真正的循环**，见主文档 §6 | 不是五个模型之一，是骨架 |
| Habit Loop | Pattern 的**四个字段**（触发 / 旧反应 / 新反应 / 保留的回报） | 不是一个流程 |
| 身份三层 | **一句自动生成的总结**，不需要任何人来填 | 不是功能 |
| TTM | **推断出来的标签**，可被用户否决 | 不是用户维护的字段 |
| 大五人格 | **不做**（见 §9） | 不是日更指标，也不是季度指标 |

**判据**：如果一个模型进来后需要用户"维护一个状态"，它就会被荒废。TTM 阶段的正确形态是系统算、用户否决，不是让用户选。

---

## 2. 四层数据

| 层 | 频次 | 打字 | 表 | 回答 |
|---|---|---|---|---|
| **事件反思** | 每个模式一次 | 9 段（已有） | `things`（不动） | 这个模式长什么样 |
| **模式 Pattern** | 一季度几个 | 4 段 | `patterns`（新） | 我在练什么 |
| **练习 Practice** | 一天 0~3 次 | **0** | `practices`（新） | 今天这次我做到了没有 |
| **回报 Outcome** | 季度一次 | 三档 | `pattern_reviews`（新，可后置） | 它到底有没有用 |

**为什么 Pattern 和 Practice 必须分成两张表**：和「时间块 vs 事件反思」是同一个理由（主文档 §4.7）——一个高频零打字，一个低频高打字，合表必然互相污染。这次不是重复犯错，是同一个原则的第二次应用。

## 3. Pattern（模式）

### 3.1 字段

| 字段 | 类型 | 说明 | 可空 |
|---|---|---|---|
| `id` | string | Guid | 否 |
| `title` | string | 模式名，如「压力下不冲动反驳」 | 否 |
| `trigger` | string | 触发场景，如「开会被质疑」 | 是 |
| `old_response` | string | 旧自动反应，如「立刻反驳/沉默憋着」 | 是 |
| `new_response` | string | 替代的**极小**行为，如「先问一句‘你的意思是…’」 | 否 |
| `reward` | string | 保留的那份回报，如「掌控感」。Habit Loop 强调：不要删回路，保留回报、换中间行为 | 是 |
| `stage` | int | 1 前沉思 / 2 沉思 / 3 准备 / 4 行动 / 5 维持 / 6 已自动化 | 否 |
| `stage_source` | int | 0 系统推断 / 1 用户手动否决 | 否 |
| `status` | int | 0 活跃 / 1 暂停 / 2 已自动化 / 3 放弃 | 否 |
| `created_at` / `updated_at` / `deleted` | — | 同其他表 | — |

**只有 `title` 和 `new_response` 是必填。** 其余可空——建模式时你可能只想清楚了一半，那就先建，用起来再补。

**活跃上限 3 个**（与目标层 `goals` 上限一致）。建第 4 个时提示"已有 3 个在练，先暂停一个？"。
理由不是爹味，是录入页顶部那块（§4.2）放不下：3 个模式就是 6 个按钮，直接吃掉首屏。
录入页只显示**最近 14 天有练习的 2 个**，其余折叠成「还有 1 个在练」。

### 3.2 阶段推断（不让你填）

| 条件 | 推断 |
|---|---|
| 创建 < 7 天且无练习 | 3 准备期 |
| 有练习，累计 ≤ 2 次 | 4 行动期（刚开始） |
| 连续 3 周，每周新反应 ≥ 2 次 | 5 维持期 |
| 连续 8 周每周 ≥ 1 次，且旧反应为 0 | 6 可能已自动化 → 提议改成「已自动化」状态 |
| 30 天无练习 | 进「静默」区（不是失败，不扣分，与目标的停滞同一套机制） |

`stage_source = 1` 时系统不再改写阶段，只在你手动点「重新推断」时恢复。

### 3.3 「已自动化」是唯一会自动提议的终态

连续 8 周旧反应为 0，系统问：「『压力下不冲动反驳』还发生过吗？要不要标记为已自动化？」

标记后从活跃列表移走，但**不删除**——它的历史是身份证据的一部分，删了证据就断了。

## 4. Practice（练习）

### 4.1 字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | Guid |
| `pattern_id` | string | 属于哪个模式 |
| `occurred_at` | int64 | 这次触发发生在什么时候（Unix 毫秒） |
| `result` | int | **1 = 用了新反应 / 0 = 回到旧反应** |
| `note` | string | 可空，一般不用 |
| `source_event_id` | string | 可空，若这次练习来自某条事件反思 |
| `created_at` / `updated_at` / `deleted` | — | 同其他表 |

**没有时长，没有情绪，没有百分比。** 它是一条事件，不是一段投入。

### 4.2 录入：1 次点击

放在**录入页最上方**一小块，不在目录里（目录是一天点 3 次的地方，不是每次触发都要进的地方）：

```
今天守住了吗
压力下不冲动反驳              ┌──────────────┐   ┌────────┐
                              │   守住了      │   │ 又回去了 │
                              └──────────────┘   └────────┘
晚上 22 点后不刷手机          ┌──────────────┐   ┌────────┐
                              │   守住了      │   │ 又回去了 │
                              └──────────────┘   └────────┘
```

点一下 = 记录完成，**1 次点击，0 打字**。不弹确认，不跳页，存完留在原地可再点一次（一天触发多次就是多点几次）。

**三条形态规则（v0.1 修正，理由见 §13.3）**

1. **正向在左、且是主按钮。** 文案是「今天守住了吗」，不是「今天犯规了吗」。默认动作必须是"守住"——因为"没做的事"本来不会留下任何痕迹，界面再去强调失败，等于替用户确认"你一直在失败"。
2. **负向按钮字号小一半、无边框。** 不是隐藏，是降低视觉权重。
3. **只在"你想起来的时候"点。** 界面上明确写这行小字。
   压根没意识到自己正在触发，既不是守住也不是失败，**不点 = 没记录 ≠ 失败**。第三态不做成按钮（见 §13.4）。

**允许事后补**：`occurred_at` 默认是**今天**，不是"现在"。点完下方一行小字可改成「刚刚 / 今天早些时候 / 昨天这时候」。压力上来的当时你不会掏手机，这是必须接受的现实；而默认成"现在"会让整条归因链从第一条起就偏（见 §13.2）。

**旧反应可以从时间块派生**：时间块列表长按 →「记一次旧反应」。
因为旧反应往往已经作为时间块存在了（比如刷手机 90 分钟），不该让你记两遍（见 §13.3）。

### 4.3 反 Goodhart：不显示成功率

**界面永不出现百分比。** 只显示：

- 本月新反应次数（如「12 次」）
- 累计次数
- 最后一次是什么时候
- 最近 8 周的**次数**柱状

一旦出现「成功率 78%」，人就会开始不记失败的那次。而 TTM 说得很清楚：**复发不是失败，是循环里正常的一环。** 一个比率会把这句话变成自欺。

只累计次数，只看趋势方向。

## 5. 事件反思的角色：模式的生产车间

### 5.1 现有 9 段表单不改（已定）

9 段写得累，但它产出的是一个模式的**完整拆解**，而这件事一个模式一辈子只做一次。所以保留，包括它的全必填。

### 5.2 加一个出口：固化

保存成功后，页面底部出现一张卡（不打断保存）：

```
这是一个会重复出现的模式吗？
[ 固化为模式 ]   [ 只是一次性的事 ]
```

点「固化为模式」→ 进入预填页：

| Pattern 字段 | 从 9 段的哪来 |
|---|---|
| `title` | 取「客观简述」前 12 字，可改 |
| `trigger` | 「客观简述」（只写事实的那段，正好是 Cue） |
| `old_response` | 「当时采取的行动」（正好是 Routine） |
| `new_response` | 「后续行动计划」（正好是设计的新行为） |
| `reward` | 「事件最终结果」 |

**你只需要改几个字，然后确认。** 这是整个字节方案里唯一一次"深度打字"，而且它复用了你已经写过的内容——不用重打。

### 5.3 之后的同类场景，不再写 9 段

同一模式再次触发时，只走 §4.2 的两个按钮。**这就是整套设计的成本曲线：第一个月写 2 篇 9 段，之后全是点击。**

如果某次特别值得深挖，仍然可以写一篇新的 9 段反思，并 `source_event_id` 关联到同一个模式。这是例外，不是常态。

### 5.4 入口收口：深写只从一个地方进

R5 之后，同一件事有两个入口（点击记练习 / 写 9 段），用户会犹豫，而犹豫的成本比多打 30 字更高。

所以：**9 段的常规入口放在 Pattern 详情页的「写一篇深挖」**，从那里进的 9 段自动带上 `source_event_id`。
录入目录里的「事件反思」保留，用于"还没有对应模式的、第一次出现的事"——那是模式的生产入口，不是练习入口。

### 5.5 一行事件（R3 起步，R5 展开）

**事发当晚写不了 9 段，而写不了就永久丢。** 这是走查里真实丢掉过一条的场景（§13.1）。

所以目录里加一个极轻的入口：**只写一行，20 字以内，不分类、不校验**，存成 `things.status = 0` 的草稿：

```
刚才开会被质疑，我又顶回去了
```

之后任何一天想展开，从这一行进 9 段，**「客观简述」预填这一行**。
这是「允许半条记录」这条原则的第三次应用：时间块一次、模式一次、现在是事件一次。

## 6. 与时间块的关联：统计层，不是录入层

**不改任何表结构，不加任何外键，录入时不多做一个动作。**

### 6.1 事后反查触发场景

Practice 有 `occurred_at`，时间块也有时间。事后 JOIN 一次：

```
对每条 practice，找 occurred_at 前后 3 小时窗口内的块
→ 取时长最长（或最近）的那条，取其 piece_code 作为「当时在干什么」
```

输出（Pattern 详情页）：

> 你标记「旧反应」的 12 次里，**8 次发生在「开会」结束后的两小时内**。

**为什么这件事必须靠数据，不能靠回忆**：Habit Loop 的核心是「保留触发、替换中间行为」，但人最难的就是认出自己的触发。你会以为是"我脾气不好"，数据会告诉你是"每次开完会"。这个差别决定你改什么。

**样本门槛（硬约束）**：少于 10 次练习时**不显示任何归因结论**，只显示"样本还不够"。
12 次里的 8 次看着像 67%，但那只是一个季度的量。小样本归因会变成新的迷信——你会为一个巧合改掉一件其实无关的事。

### 6.2 反面同样成立

时间块显示「晚上刷手机 4 小时」，Practice 显示「22 点后旧反应高发」——两个数字叠在一起，才说得清那晚到底发生了什么。

### 6.3 R2 的粗粒度就够

R2 没有计时，块只有时长档，没有精确的 `started_at`/`ended_at`。所以反查用「同一 3 小时时段」近似，够了——定位触发只需要"那段时间你在干什么"，不需要精确到分钟。

## 7. 身份三层：一句话，不是一个功能

系统在 Pattern 详情页底部生成一句，**不可编辑、不需要填**：

> 你在「压力下不冲动反驳」这件事上，**最近 6 周按新反应做了 11 次**，其中 3 周旧反应为 0。

这句话就是身份证据。它必须由数据生成，因为**一旦要你自己写"我是一个冷静的人"，它就变成了口号**，而口号不改变行为。

结果层（情绪更稳、内耗更少）不做事每日指标，放在 §8 的季度评审里。

---

## 8. Outcome：季度三档，不每天填

每季度对每个活跃 Pattern 问一次，三个按钮：

```
「压力下不冲动反驳」现在怎么样了？
[ 明显好转 ]  [ 有点变化 ]  [ 还那样 ]
```

存 `pattern_reviews`：`pattern_id` / `reviewed_at` / `outcome`(1~3) / `note`(可空)。

**不做每日主观打分。** 每天问"今天内耗几分"会变成负担，而且分数会随天气波动，没有信息量。

---

## 9. 大五人格：不做（已定）

理由不是"低频"，而是**它没有可执行含义**。尽责性从 3.2 到 3.5，你拿这个数字做不了任何决定。

它唯一的用途是"证明我没退步"，而这需要连续两年以上的数据才有说服力。放进软件，就是一块一年开两次的墓碑。

想做的时候：在外部测，把结果写一条事件反思存着就行。零成本，也不占界面。

## 10. 需求边界

### 10.1 做（R5）

1. `patterns` 表 + 列表 / 新建 / 详情（活跃上限 3）
2. 事件反思保存后的「固化为模式」（预填 4 段）
3. 录入页顶部「今天守住了吗」+ 1 次点击记录练习（正向为主按钮，负向弱化）
4. 阶段推断（含"可能已自动化"的提议）
5. 时间戳反查触发场景（纯查询，不改表；**样本 < 10 次不下结论**）
6. 季度 Outcome 三档
7. 身份证据那一句话（自动生成）
8. 练习时点可改（默认"今天"，可选"刚刚 / 今天早些时候 / 昨天这时候"）
9. 时间块长按 →「记一次旧反应」（从已有数据派生，避免重复录入）
10. Pattern 详情页的「写一篇深挖」→ 进 9 段并自动带 `source_event_id`

### 10.2 不做

| 不做 | 理由 |
|---|---|
| 显示成功率 / 百分比 | 反 Goodhart，人会开始不记失败 |
| 连续打卡天数 | 复发是正常环，断签是放弃的头号原因 |
| 每日主观打分（内耗几分） | 波动大、无信息量、必成负担 |
| 大五人格问卷 | 没有可执行含义（§9） |
| 让用户自己选 TTM 阶段 | 两个月后必过期（§3.2 改为推断） |
| Pattern 的层级 / 子模式 | 引入层级就有规划成本 |
| 时间块与 Practice 的显式外键 | 时间戳邻近已够，外键会让录入多一步（§6） |
| 把 Pattern 并进时间块 / 事件反思表 | 高频零打字与低频高打字不能同表 |
| 提醒推送（"今天还没练"） | 会让这件事变成债 |
| 改 9 段表单的字段与必填 | 它是模式的生产车间，写得累是对的（§5.1） |
| 第三个按钮「压根没意识到」 | 这一态本来无法记录；做成按钮会把"没注意"变成又一件要维护的事（§13.4） |
| 高于 3 个活跃模式 | 录入页顶部会膨胀成按钮墙（§3.1） |

### 10.3 排期理由

Pattern 排 R5，不是因为它次要，而是**你还不知道自己该建哪个模式**。

现在凭想出来的，大概率是「我要更自律」「我要少焦虑」这种没法执行的东西。三个月的时间块数据会告诉你：时间实际花在哪、哪些时段最失控。**先用数据认出触发，再拆解模式。**

## 11. 验收标准

### 11.1 成本

- [ ] 记录一次练习 ≤ 1 次点击，无弹窗、无跳页
- [ ] 固化一个模式 ≤ 5 分钟（含改字），且不需要重打 9 段内容
- [ ] 从事件反思进入固化流程，预填字段命中率 ≥ 3/5（不用改太多）
- [ ] 连续记录 10 次练习，全程无键盘

### 11.2 正确性

- [ ] 修完 8 周数据后，阶段推断结果与规则表一致
- [ ] 用户手动改过阶段后，系统不再自动改写
- [ ] 30 天无练习的模式进「静默」区，不报错、不标红、不扣分
- [ ] 触发场景反查能算出「旧反应 8/12 次发生在某片之后」
- [ ] 删除一条 Practice 后，各项次数统计立即变化（证明是查询）

### 11.3 反 Goodhart

- [ ] 全应用搜索不到 Pattern 相关的百分比与成功率
- [ ] 没有"连续 N 天"这类计数

### 11.4 走查补出的验收项

- [ ] 练习录入的默认动作是「守住了」，且它在视觉上是主按钮（字号 / 位置优先于负向）
- [ ] 点完练习，`occurred_at` 默认是"今天"，可改成"刚刚 / 今天早些时候 / 昨天这时候"
- [ ] 不点任何按钮 → 不产生记录，界面上没有任何"你没记录"的提示
- [ ] 时间块长按能派生一次旧反应练习，且不需要重新选时间
- [ ] 练习次数 < 10 时，Pattern 详情页不出现任何归因结论
- [ ] 活跃模式到 3 个时，建第 4 个被拦下
- [ ] 录入页顶部最多显示 2 个模式，其余折叠

### 11.5 事件入口

- [ ] 一行 20 字可独立存成草稿，不要求任何其他字段
- [ ] 从草稿进 9 段时，「客观简述」已预填那一行

|---|---|---|
| `Pattern` 作为高频 Activity 记录 | 拆成 Pattern（低频设计）+ Practice（高频点击） | 五个字段都是深度思考产物，高频填必崩 |
| 「标记 AssetBuild」 | 取消 | 点「新反应」本身就是证据，多一个旗标只会忘 |
| Outcome 每日填主观回报 | 季度三档 | 每日打分必成负担且无信息量 |
| 「发生场景时作为 Activity 记录」 | 允许事后补记 | 压力上来的当时不会掏手机 |
| 大五低频测量 | 不做 | 低频不是问题，没有可执行含义才是 |
| 不显示成功率之外的一切 | 明确禁止显示成功率 | 它未考虑 Goodhart，这是致命缺口 |

## 13. 五个月使用模拟暴露的 5 个缺口

模拟设定：一个人、一个具体模式（"被质疑时不立刻反驳"）、五个月真实时间。

### 13.1 事发当晚写不了 9 段，而写不了就永久丢

真实场景：周三下午被 review 质疑、当场顶回去，晚上 23:40 想记，盯着「客观简述」两分钟，写了四十字，关掉睡了。第二天那条没了——**因为现在没有草稿态**。

解法：§5.5 的「一行事件」。20 字，不分类，存草稿，日后展开时预填。

### 13.2 `occurred_at` 默认 now，会让整条归因链从第一条起就偏

练习几乎永远是事后补的（触发当时不可能掏手机）。默认"现在"意味着记的时点系统性偏移几小时，而 §6 的触发反查正是靠这个时点做前后 3 小时窗口匹配。

默认值错，结论就错，而且错得看不出来。

解法：默认"今天"，可选档位；时间块派生的练习直接继承块的时间。

### 13.3 【最要紧】"没做的事"没有数据，系统天然偏向记录失败

**这条推翻了本文件 §2 的一个隐含假设**：以为两个按钮是对称采集。实际完全不对称——

- 「又回去了」有具体时间、地点、对话，好记；
- 「守住了」是一次**没发生**的事，你根本不会想起去点。

三个月后你会看到一个"失败率很高"的模式然后放弃。**不是因为真的失败，是因为只有失败被记录了。**

所有靠"记录"驱动的自我改造工具都死在这里。对策三条：

1. 正向为主按钮：「今天守住了吗」而不是「今天犯规了吗」。
2. 旧反应可从时间块派生（它往往已经作为时间块存在了，如刷手机 90 分钟），不必记两遍。
3. 不显示比率（§4.3 已有），只显示次数与趋势。

### 13.4 「压根没意识到」是第三态，但不做成按钮

触发发生了、当时完全没想起来要练——既不是守住，也不是失败。若只有两个按钮，用户会把它记成"又回去了"，于是"旧反应"这个数字里混了两种改法完全不同的东西（控制反应 vs 提高觉察）。

**决定：不加第三按钮。** 因为"没意识到"本来就不该产生记录（不知道自己不知道的东西无法记录），做成按钮会把"没注意"变成又一件要维护的事。只在文案上写明"只在你想起来的时候点"，不点 = 没记录 ≠ 失败。

### 13.5 活跃模式没有上限

3 个模式 = 6 个按钮，直接吃掉录入页首屏。上限 3（同 `goals`），录入页只显示最近 14 天有练习的 2 个。

### 13.6 两条小调优

| 项 | 规则 |
|---|---|
| 归因样本门槛 | 练习 < 10 次不显示任何归因结论，只显示"样本还不够" |
| 9 段入口收口 | 常规入口移到 Pattern 详情页的「写一篇深挖」，自动带 `source_event_id`；目录里的「事件反思」只服务"第一次出现的事" |

### 13.7 模拟中被验证为"对的"的三件事

刻意记下来，避免以后被"优化"掉：

1. **断一个月回来不用重新开始**：没有红点、没有"你已经 28 天没练习"、没有连续打卡。第 18 周点一次，它跟没断过一样。
2. **提议只问一次**：连续 8 周旧反应 0 时提议"标记为已自动化"，用户选"再观察一个季度"后就不再问。第二天再问一次会导致功能被关掉。
3. **预填不是为了省字，是为了让"决心"和"能执行的行为"并置**。原 9 段里写的"以后要注意控制情绪"被摘出来当按钮时才显得荒谬，用户因此才改成"先问一句：你指的是哪一部分？"
